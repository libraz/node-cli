# 用語集

このドキュメント全体で使う用語を、英語表記のアルファベット順に並べています。

### AbortSignal

すでに動いているコードに「今すぐ止まれ」という通知を運ぶ、JavaScript 標準のオブジェクトです。シグナルを持つコードは `signal.aborted` を調べるか `abort` イベントを購読でき、`fetch`、タイマー、ストリーム操作といった多くの組み込み API はこれを直接受け取って、発火したら処理を諦めます。すべてのコマンドは `ctx.signal` としてこれを受け取ります。中断されるのはコマンドがキャンセルされたとき、つまり利用者が Ctrl-C を押したときです。時間のかかる処理では、これを下位に渡すか監視して、キャンセルが実際に効くようにしてください。[コマンド](commands.md)を参照してください。

### エイリアス（alias）

コマンドやオプションの別名です。`.alias("g")` と書けば `myapp g World` は `myapp greet World` と同じ意味になり、`"-u, --uppercase"` は `-u` を `--uppercase` のエイリアスとして宣言します。エイリアスが存在するのは入力面だけです。`ctx.commandPath` は常に正式なコマンド名を返し、`ctx.options` のキーは常に長いオプション名です。[コマンド](commands.md)と[オプション](options.md)を参照してください。

### ANSI エスケープシーケンス

エスケープ文字で始まる短い文字列で、端末はこれを表示すべき文字ではなく命令として解釈します。色、太字、カーソル移動、行のクリアは、いずれもこの仕組みで行われます。ライブラリは色付き出力と進捗表示の再描画のためにこれを出力し、出力先が端末でないときは省きます。リダイレクトしたログファイルが読めない制御文字で埋まることはありません。`stripAnsi()` は文字列からこれを取り除き、`stringWidth()` は端末が表示するとおりの幅を測ります。[カラー](color.md)を参照してください。

### 位置引数（positional argument）

名前ではなくコマンドライン上の位置で識別される入力です。`myapp greet World` の `World` は、コマンドが `greet <name>` と宣言されているため `name` に束縛される位置引数です。山括弧が必須、角括弧が省略可能を表します。位置引数の値は宣言した名前をキーとして `ctx.args` に入り、常に文字列です。ライブラリは型変換を一切行いません。[コマンド](commands.md)を参照してください。

### argv

プログラムの起動時に OS が渡す語のリストです。Node では `process.argv` がそれで、先頭 2 要素は Node 実行ファイルのパスとスクリプトのパスであり、利用者の入力は添字 2 から始まります。`cli.start()` は既定で `process.argv.slice(2)` を使いますが、配列を明示的に渡すこともできます。テストからコマンドを動かすときはこの方法を使います。渡された配列そのものは、コマンドからも `ctx.rawArgv` として参照できます。[入門](getting-started.md)を参照してください。

### バナー（banner）

対話シェルが開いたときに、最初のプロンプトの上へ一度だけ表示される行です。既定ではアプリケーション名とバージョン（`myapp v1.0.0`）で、バージョンを設定していなければ名前だけになります。`banner` に文字列を設定すると差し替わり、空文字列を設定すると表示されなくなります。直接実行モードでは表示されません。[対話シェル](interactive-shell.md)を参照してください。

### コマンドパス（command path）

入れ子構造の中でコマンドを特定する名前の並びです。`myapp db migrate` はコマンドパス `["db", "migrate"]` に解決され、コマンドからは `ctx.commandPath` として読めます。パスは常に正式名です。エイリアス経由で到達した場合も本来の名前が入るため、複数の入口で共有しているハンドラは、エイリアスを一つずつ突き合わせなくても自分がどのコマンドとして呼ばれたかを判別できます。[コマンド](commands.md)を参照してください。

### 直接実行モード（direct mode）

引数がある場合に使われる実行モードです。1 つのコマンドを解析して 1 回実行し、プロセスが終了します。`myapp greet World` は直接実行モードです。このモードでは `ctx.shell` が `null` になるので、アクションは対話シェルの外で動いていることを判別できます。`cli.start()` は、引数リストが空でなければこのモードを選びます。[入門](getting-started.md)を参照してください。

### ESM（ECMAScript モジュール）

`import` と `export` を使う、JavaScript 標準のモジュール形式です。Node は `require()` を使う古い CommonJS 形式もサポートしており、プロジェクトはどちらを使うかを `package.json` の `"type": "module"` で宣言します。このライブラリは ECMAScript モジュールとしてのみ公開しているため、利用側のプロジェクトには `"type": "module"` が必要で、`require()` では読み込めません。[入門](getting-started.md)を参照してください。

### 終了コード（exit code）

プロセスが終了時に報告する小さな整数で、起動元に実行が成功したかどうかを伝えます。0 が成功、それ以外は失敗で、シェルスクリプトや CI システムはこの値で分岐します。ライブラリはプロセスを唐突に終わらせるのではなく `process.exitCode` を設定するため、バッファに残った出力が先に吐き出されます。キャンセルされたコマンドは 130、終了シグナルで停止した対話シェルは 143 で終わります。[エラー](errors.md)を参照してください。

### フラグ（flag）

値を取らず、指定されていること自体が意味を持つオプションです。`--uppercase` や `-v` がこれにあたります。このライブラリでいうフラグは、`type: "boolean"` で宣言したオプションを指します。指定されると `true` に解決され、さらに否定形も受け付けるので `--no-uppercase` は `false` に解決されます。[オプション](options.md)を参照してください。

### 書記素（grapheme）

読み手が 1 文字と感じるテキストの単位で、複数の Unicode コードポイントから組み立てられることがあります。肌の色修飾子つきの絵文字や、結合アクセントが後続する文字がその例です。文字列の `.length` が数えるのはコードユニットであって書記素ではありません。素朴な桁揃えが絵文字やアクセント付き文字で崩れるのはこのためです。ライブラリはテキストを書記素に分割して、テーブルの列と切り詰めを揃えます。この分割は `splitGraphemes()` が公開しており、`stringWidth()` は端末で 2 列を占める東アジア文字も勘定に入れます。[カラー](color.md)と[テーブル](table.md)を参照してください。

### 対話シェル（interactive shell）

端末で引数なしに起動されたとき、ツールが自身の内側に開くプロンプトです。そこに打たれた各行は、直接実行モードと同じコマンド定義を通して解析・実行されます。シェルはさらに、永続化される履歴、タブ補完、コマンド間のパイプ、モードを加えます。シェルの中で動くコマンドは、`ctx.shell` に `null` ではなくシェルオブジェクトを受け取ります。[対話シェル](interactive-shell.md)を参照してください。

### モード（サブ REPL）

対話シェルを一時的に押し込める状態で、この間に打たれた各行はコマンドとして解析されず、1 つのハンドラに渡ります。たとえば `sql` コマンドが、各行を問い合わせとして扱うモードに入り、独自のプロンプト文字列、独自の補完、ディスクには書き出さない独自のメモリ内履歴を持つ、といった使い方ができます。モードにはコマンドから `ctx.shell` 経由で入り、抜けると通常のプロンプトに戻ります。[対話シェル](interactive-shell.md)を参照してください。

### オプション（option）

先頭にダッシュを付けて書く名前付きの入力で、順序を問わず指定できます。`--port 8080`、`-p 8080`、`--uppercase` がその例です。オプションは `.option()` と[オプションスキーマ](#オプションスキーマoption-schema)で宣言します。解析された値は `ctx.options` に入り、キーは常にダッシュを外した長い名前で、エイリアスがキーになることはありません。位置引数と違い、オプションには型を付けられ、既定値を持たせられ、検証もかけられます。[オプション](options.md)を参照してください。

### オプションスキーマ（option schema）

1 つのオプションの振る舞いを記述するオブジェクトです。`type`（`string`、`number`、`boolean`、またはその配列形）、短い `alias` 名、`required` かどうか、`default`、値を制限する `choices`、独自の `parse` 関数、独自の `validate` 関数、ヘルプから `hidden` にするかどうか、そして補完候補を持ちます。これが `.option()` の第 2 引数で、ヘルプでの表示のされ方も含め、ライブラリがそのオプションについて知っていることはすべてここから来ます。[オプション](options.md)を参照してください。

### パイプ（pipe）

`|` の文字で書く、あるコマンドの出力を別のコマンドの入力につなぐ仕組みです。対話シェルの中で `list | grep alpha` と打つと両方のコマンドが走り、前者の標準出力が後者の `ctx.stdin` に流れ込みます。これが効くのは同じアプリケーション内で定義されたコマンド同士だけで、しかもシェルのプロンプトに打った行に限られます。OS のパイプではなく、シェル自身のパイプです。コマンドをパイプラインで使えるものにするのは、`console.log` ではなく `ctx.stdout` に書くという点です。[対話シェル](interactive-shell.md)を参照してください。

### プラグイン（plugin）

コンテキストオブジェクトを受け取り、それを使って既存のアプリケーションにコマンド、イベントリスナー、フォールバックハンドラを登録する関数です。プラグインは `cli.use()` で取り付け、どのコマンドよりも先に完了を待たれます。そのため、設定を読み込んだりサービスに問い合わせたりしてから、何を登録するかを決められます。プラグインが例外を投げた場合は致命的で、失敗が報告されコマンドは実行されません。[イベントとプラグイン](events-and-plugins.md)を参照してください。

### プロンプト（入力関数）

`prompt` は、利用者に質問して答えを返すメソッドを持つ、エクスポート済みのオブジェクトです。メソッドは `prompt.text()`、`prompt.confirm()`、`prompt.select()`、`prompt.multiselect()`、`prompt.password()` です。これらはコマンドのアクションの中から使い、読み取りには端末が必要です。次の項のプロンプト文字列とは別物です。[プロンプト](prompts.md)を参照してください。

### プロンプト（文字列）

対話シェルで各入力行の先頭に表示され、入力の開始位置を示す文字列です。既定は `"> "` で、`createCLI()` の `prompt` オプションか `cli.prompt()` で設定します。モードは、有効な間だけ独自のプロンプト文字列に差し替えられます。前の項のプロンプト入力関数とは別物です。[対話シェル](interactive-shell.md)を参照してください。

### REPL

read–eval–print loop の略で、入力行を読み、それに応じて動作し、結果を表示してプロンプトに戻る、という繰り返しを行うプログラムです。引数なしで起動した Node の `node` コマンドもそのひとつです。このライブラリの対話シェルは、語彙が JavaScript の式ではなくアプリケーションのコマンドである REPL です。[対話シェル](interactive-shell.md)を参照してください。

### シバン（shebang）

実行可能スクリプトの先頭に置く `#!/usr/bin/env node` の行です。ファイルを直接実行すると、OS はこの行を読み、名指しされたプログラムにそのファイルを入力として渡して起動します。ここでは `env node` が名指しされており、現在の `PATH` から `node` を探します。JavaScript はこの行をコメントとして扱うため、import されるファイルに残っていても害はありません。macOS と Linux では必須で、Windows では無視されます。[入門](getting-started.md)を参照してください。

### SIGINT / SIGTERM

OS が動作中のプロセスに送るシグナルです。SIGINT は Ctrl-C が送るもので「これを中断せよ」を意味し、SIGTERM は終了してほしいという穏当な要求で、多くはプロセスマネージャから届きます。ライブラリは SIGINT をキャンセルに変換します。`ctx.signal` が中断され、登録済みのキャンセルハンドラが走るため、コマンドは止まる前にロックファイルを消したり接続を閉じたりできます。2 回目の Ctrl-C は終了コード 130 で強制終了し、対話シェルは SIGTERM を受けると後片付けをして 143 で終了します。[エラー](errors.md)を参照してください。

### stderr

標準エラー。あらゆるプロセスが持つ 2 番目の出力ストリームで、慣習として診断、警告、エラーメッセージに使います。標準出力とは別なので、`myapp export > data.json` はデータだけを取り込み、ログ行は端末に出たままになります。コマンドは `ctx.stderr` を通してここに書き、`logger()` も既定でここを使います。[ログ出力](logging.md)を参照してください。

### stdin

標準入力。プロセスが入力を読むストリームで、通常はキーボードですが、`<` でリダイレクトすればファイル、パイプでつなげば別のコマンドの出力になります。コマンドは `ctx.stdin` を通して読み、入力ストリームがない場合これは `null` です。標準入力が端末かどうかは、`cli.start()` が対話シェルを開く前に確かめる 2 つの条件のうちの 1 つです。[入門](getting-started.md)を参照してください。

### stdout

標準出力。プロセスが結果を書き出すストリームで、通常は端末ですが、リダイレクトやパイプをすればファイルや別のコマンドになります。コマンドは `console.log` ではなく `ctx.stdout` を通して書きます。そうすることで、対話シェルの中のパイプラインやテストから出力を取り込めます。[コマンド](commands.md)を参照してください。

### サブコマンド（subcommand）

別のコマンドの下に入れ子になったコマンドで、`myapp db migrate` のように両方の名前を挙げて呼び出します。サブコマンドは、アプリケーションではなくコマンドビルダーに対して `.command()` を呼んで作ります。自前のアクションを持たない親は名前空間として振る舞い、単独で呼ばれるとサブコマンドの一覧を表示します。入れ子は 1 段より深くできます。[コマンド](commands.md)を参照してください。

### タブ補完（tab completion）

Tab キーを押して、入力中の続きをツールに補わせたり候補を出させたりする操作です。対話シェルの中では、オプションスキーマや `.complete()` ハンドラが与える候補を使って、コマンド名、サブコマンド、オプションのフラグ、オプションの値を補完します。効くのはツール自身のプロンプトだけです。ライブラリは bash・zsh・fish 用の補完スクリプトを生成しないため、システムシェルのプロンプトで Tab を押すとファイル名が補完されます。[対話シェル](interactive-shell.md)を参照してください。

### TTY（端末）

teletype の略で、実際上は「端末につながっている」ことを指します。ストリームは、対話的な端末ウィンドウにつながっていれば TTY であり、ファイルにリダイレクトされたりパイプにつながれていれば TTY ではありません。この区別で切り替わる挙動が 2 つあります。色と進捗のアニメーションは TTY にだけ出力され、対話シェルは標準入力と標準出力の両方が TTY のときにだけ開きます。判定は `streamIsTTY()` が行います。[入門](getting-started.md)を参照してください。

### 可変長引数（variadic argument）

ちょうど 1 つではなく残りの値をすべて集める位置引数で、先頭に省略記号を付けて宣言します。`copy <...files>` は `ctx.args.files` を文字列の配列に束縛します。可変長引数は後ろにあるものをすべて消費するため、最後に置く必要があります。ほかの位置引数と同じく、集めた値は文字列で、変換はされません。[コマンド](commands.md)を参照してください。
